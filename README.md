# downloader

Консольный загрузчик файлов на Go. Скачивает несколько файлов одновременно, каждый файл делит на чанки и качает их параллельно. Умеет продолжать загрузку после обрыва и корректно останавливается по Ctrl+C.

```
$ ./downloader ./downloads https://example.com/data.zip https://example.com/report.csv
data.zip   [=============>------------------------]  35 %  17.5 MiB / 50.0 MiB
report.csv [=================================>----]  90 %    4.5 MiB / 5.0 MiB
```

## Возможности

- **Параллельная загрузка.** Файлы качаются одновременно. Каждый файл делится на чанки по 10 MiB, и их скачивает пул из 8 воркеров через HTTP `Range`-запросы.
- **Докачка.** Рядом с файлом ведётся `<имя>.progress` со списком скачанных чанков. При повторном запуске загрузка продолжается с того места, где остановилась.
- **Повторные попытки.** Неудачный чанк перезапрашивается до 3 раз с паузой 2 секунды.
- **Graceful shutdown.** По Ctrl+C программа перестаёт брать новые чанки, дожидается текущих, сохраняет состояние и выходит.
- **Прогресс-бары.** Для каждого файла отдельная строка с процентом и объёмом скачанного ([mpb](https://github.com/vbauerster/mpb)).

## Сборка

Нужен Go 1.26 или новее.

```bash
git clone https://github.com/egorka-hub/downloader.git
cd downloader
go build -o downloader .
```

## Использование

```bash
./downloader <директория> <url1> [url2 ...]
```

| Аргумент | Описание |
|---|---|
| `<директория>` | Куда сохранять файлы. Создаётся, если её нет |
| `<url>` | Один или несколько адресов. Имя файла берётся из последней части URL |

### Примеры

Скачать один файл:

```bash
./downloader ./downloads https://example.com/data.zip
```

Скачать несколько файлов одновременно:

```bash
./downloader ./downloads https://example.com/data.zip https://example.com/images.tar
```

Прервать и продолжить:

```bash
./downloader ./downloads https://example.com/big.iso
# ^C
# Получен сигнал прерывания, завершаем работу...
# Ожидание завершения текущих загрузок...
# big.iso: состояние сохранено
# Выход

./downloader ./downloads https://example.com/big.iso   # продолжит с места остановки
```

### Код выхода

| Код | Когда |
|---|---|
| `0` | Все файлы загружены |
| `1` | Ошибка аргументов, ошибка загрузки или прерывание по Ctrl+C |

## Как это устроено

1. `HEAD`-запрос узнаёт размер файла (`Content-Length`).
2. Файл на диске сразу создаётся нужного размера, а затем делится на чанки.
3. Недокачанные чанки попадают в очередь (канал), из которой их разбирают воркеры. Каждый воркер скачивает свой диапазон байт и записывает его в файл по нужному смещению (`WriteAt`).
4. После каждого чанка обновляется `.progress`-файл:

   ```json
   {
     "url": "https://example.com/data.zip",
     "total_size": 52428800,
     "chunk_size": 10485760,
     "total_chunks": 5,
     "downloaded_chunks": [true, true, false, true, false]
   }
   ```

   Если файл на сервере изменился (другой размер или URL), состояние сбрасывается и загрузка начинается заново.

5. Ctrl+C отменяет общий `context.Context`. Воркеры проверяют его перед каждым новым чанком.

Размер чанка, число воркеров и параметры повторов задаются константами в начале `main.go`.

## Ограничения

- Сервер должен отдавать `Content-Length` и поддерживать `Range`-запросы (ответ `206 Partial Content`).
- Каждый чанк перед записью целиком держится в памяти: до 8 × 10 MiB на файл.
- Если у двух URL совпадает последняя часть пути, файлы перезапишут друг друга.
